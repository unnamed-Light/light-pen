# Данные и задачи в разработке 0.4

Это описание реализованного этапа, а не объявление полного релиза. Сохраняется Fluent-интерфейс и одна сменяемая боковая панель. Новые настройки открываются внутри редактора таблицы/задачи; представления задач доступны через «Вставить объект → Планирование задач…».

## Таблицы

Формат 4 добавляет `grid.rows` и `grid.columns`. Каждый идентификатор строки/поля постоянен в пределах таблицы. `cells` остаётся переносимой прямоугольной матрицей; её индексы соответствуют последовательностям `grid`. Первая строка содержит названия полей. Для прежних файлов идентификаторы вычисляются детерминированно (`r0`, `c0` и т. д.) и записываются при редактировании. Вставка, удаление и сортировка переставляют данные вместе с их идентификаторами. Копии таблицы имеют независимый ID объекта; внутренние ID ограничены этой таблицей.

Типы: текст, число, дата, флажок, выбор и HTTP/HTTPS-ссылка. Числа принимают десятичную запятую; нечисловые значения не превращаются в ноль. Даты проверяются по реальному календарю. Ошибочные значения сохраняются как исходный текст и отмечаются в редакторе. Это позволяет исправить импортированные данные и не терять их при смене типа.

Раскрываемый раздел содержит поиск, сортировку, фильтр ошибок, количество заполненных значений и числовые сумму/среднее. Поиск и порядок предпросмотра не меняют файл. «Применить порядок» записывает перестановку; вся работа в диалоге остаётся одной операцией undo после «Применить». «Отмена» сохраняет прежнее состояние.

CSV/TSV разбираются с кавычками, Unicode, CRLF и переносами внутри ячейки. CSV определяет запятую/точку с запятой по заголовку. Импорт ограничен 2 МБ, 100 строками, 50 столбцами и 10 000 символами в ячейке; лимиты проверяются во время разбора. CSV-экспорт содержит BOM для Excel и превращает формулоподобный текст в текстовое значение. Отрицательные числа остаются числами. Нативный текстовый экспорт ограничен 8 МБ и использует атомарную запись.

Жёсткий лимит файла выше ограничений обычного добавления: 1000 строк, 200 столбцов и 50 000 ячеек. Запас нужен в том числе для одновременных вставок несколькими участниками. Это не обещание мгновенного открытия DOM-редактора на максимуме: виртуализация очень больших таблиц остаётся в полном плане.

## Задачи и представления

Карточка хранит описание, приоритет, начало/срок, оценку в часах, теги, зависимости, архив и пункты чек-листа. Пункты имеют постоянные ID. Поиск доски включает описание и теги. При конфликтующих датах и цикле зависимостей данные сохраняются, а планирование показывает проблему; автоматическое исправление не подменяет действия пользователей.

В одном диалоге переключаются канбан, календарь, таймлайн и обзор статусов. Это представления существующих карточек без отдельных копий. Статус меняется выбором или переносом в колонку и попадает в общую историю/синхронизацию. Для заблокированных карточек и наблюдателей изменения выключены; переход к исходному объекту остаётся доступен. Диагностика зависимостей отличает сам цикл от задач, зависящих от него, и работает без рекурсивного обхода.

Календарь использует понедельник и реальные диапазоны дат, включая однодневные задачи. Таймлайн имеет недельную/месячную/квартальную/годовую шкалу. Задачи без дат и за пределами шкалы явно обозначаются. Архив скрыт по умолчанию. Отчёт CSV использует текущие фильтры. Длинные списки показываются порциями по 150 карточек; календарь показывает первые три задачи дня с переходом ко всем.

## Совместное редактирование

Каждая ячейка — отдельный `Y.Text`, строки/поля — сущности в `Y.Map` и ссылки в `Y.Array`. Слияние выполняется по ID, а не по сместившемуся индексу. Одновременные вставки сохраняют обе сущности, удаление выигрывает у устаревшей правки. Если участники удалили последние разные оси, материализуется пустая редактируемая строка/поле без возвращения удалённых записей. Конкурентные переносы могут дать повторные ссылки в последовательности CRDT; отображение детерминированно устраняет повторы. Локальная перестановка очищает их для затронутой записи.

У задачи поля независимы, описание/текст пункта используют `Y.Text`, пункты — сущности по ID, теги/зависимости — наборы `Y.Map`. Локальная отмена отслеживает только собственные операции. Ранее созданное атомарное dev-состояние таблицы/задачи читается и переводится на новую структуру при первой правке; одновременное использование старого dev-клиента после миграции не поддерживается.

Остаётся полный объём данных из плана: вычисления, связи записей, общие источники канбана/календаря из произвольных типизированных таблиц, произвольные колонки/WIP/дорожки, графики из таблиц и XLSX. Текущие представления задач не закрывают эти требования.
