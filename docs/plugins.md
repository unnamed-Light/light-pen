# Плагины Light Pen — SDK 1

Плагин устанавливается из локального `.lightpen-plugin`: это JSON с `manifest` и JavaScript в `code`. TypeScript компилируется в такой же одиночный скрипт. Отдельный язык писать не нужно. В приложении: **Файл → Плагины**. Встроенный пример создаёт стикеры, карточки счётчиков и сводку страницы.

Установка добавляет выключенный плагин. Пользователь просматривает разрешения и включает его. Обновление заменяет пакет, останавливает исполнение и отзывает разрешения; настройки плагина сохраняются. JS-плагин с доступом только к доске/своим настройкам может оставаться включённым после перезапуска. Файлы, сеть и отдельный процесс требуют повторного включения. Автоматического скачивания или магазина нет.

## Пакет

```json
{
  "manifest": {
    "apiVersion": 1,
    "id": "my.first-plugin",
    "name": "Мой плагин",
    "version": "1.0.0",
    "description": "Добавляет заметку",
    "runtime": "worker",
    "permissions": ["board:write"],
    "commands": [{"id": "hello", "title": "Добавить заметку"}]
  },
  "code": "LightPen.register({hello:()=>LightPen.board.apply({create:[{kind:'sticky',x:400,y:200,width:240,height:160,text:'Привет!',fill:'#fff1a8'}]})});"
}
```

ID — строчные латинские буквы/цифры с точками, дефисами или подчёркиваниями; версия — semver. Для команды можно задать `inputSchema` и `readOnly`. Полный типизированный контракт: `src/plugins/types.ts`, ambient-декларация для одиночного TS-скрипта: `plugins/sdk.d.ts`. Исходники примеров и готовые пакеты находятся в `plugins/examples/`.

В TS-скрипте используйте `/// <reference path="путь/к/plugins/sdk.d.ts" />` и `LightPen.register(...)`. Сборка пакета из manifest и `.js`/`.ts`:

```powershell
npm run plugin:pack -- manifest.json plugin.ts my-plugin.lightpen-plugin
```

Скрипт проверяет пакет и синтаксис TS, затем убирает типы. Проверку типов выполняйте отдельно через TypeScript. Пакет исполняется как классический Worker-скрипт: runtime `import`/`export` не поддерживаются; зависимости предварительно объединяйте в один IIFE. Запуск `npm run plugin:pack` без аргументов пересобирает два примера.

## Методы

| Метод | Назначение и границы |
| --- | --- |
| `LightPen.register({commandId: async args => result})` | Регистрация объявленных в manifest команд; аргументы и результат — JSON |
| `board.read({selectionOnly, offset, limit, includeAssets, includePoints, pointOffset, pointLimit})` | Снимок текущей страницы: `id`, `pageId`, `revision`, `title`, `total`, `offset`, `next`, `widgetCount`, `elements`. По умолчанию до 100 объектов без изображения/точек; максимум 200 за страницу. Точки читаются диапазонами до 10 000. `selection` содержит первые 200 ID, `selectionCount` — полное количество; всё выделение читается через `selectionOnly` и `next` |
| `board.apply({create, update, delete, label})` | Создание объектов, `update:[{id,patch}]`, удаление ID. Все поля модели, включая таблицы, формулы, задачи, группы и связи; ID/тип существующего объекта менять нельзя. Не более 500 изменений за команду |
| `widgets.create({type, data, fallback, x, y, width, height})` | Объявленный в manifest виджет; JSON-данные и читаемый текст сохраняются вместе с обычной карточкой |
| `storage.get(key)`, `storage.set(key,value)` | Отдельные настройки этого плагина; ключ не открывает настройки другого плагина/приложения |
| `network.fetch(url,{method,body})` | GET/POST только на явно разрешённые origin; без cookies приложения, редиректов и произвольных заголовков |
| `files.read(path)`, `files.write(path,text,overwrite)` | UTF-8 текст до 1 MiB в выбранной папке; явное перезаписывание. Закрытые данные приложения недоступны |
| `ui.notify(message)` | Короткий результат внутри менеджера расширений |

Сценарий работает с активной страницей, зафиксированной в начале команды. Правки сначала проходят в отдельном кандидате, затем одним действием попадают в обычную историю, сохранение и совместное редактирование. Ошибка, смена доски/страницы, начало пользовательского ввода или отзыв разрешений не оставляют частичных правок доски. Независимые внешние действия, например уже выполненный POST или запись файла, не являются транзакцией доски.

## Разрешения и интерфейс

Разрешения: `board:read`, `board:write`, `storage`, `network`, `files:read`, `files:write`, `process`. Плагин объявляет необходимые возможности; пользователь выдаёт только выбранное. `readOnly`-команда не может менять доску, настройки плагина, файл или выполнять POST.

Декларативные `panels` задают заголовок, команду и поля `text`, `number`, `boolean`, `select`, `color`. Числа получают ползунок и точное значение. Панель показывается внутри существующего диалога, без доступа к DOM и постоянных кнопок на холсте. В `widgets` объявляются доступные типы карточек. Меняя виджет через `board.apply`, обновляйте `widget.data`, `widget.fallback` и `text` согласованно. Даже без плагина карточка видна, масштабируется, сохраняется и экспортируется. Код расширения не входит в файл доски или переносимый фрагмент.

JS выполняется в Worker, созданном доверенным загрузчиком внутри iframe с отдельным opaque origin. Пакет не получает `invoke`, DOM, хранилище приложения или прямую сеть. Родительский CSP разрешает фиксированный загрузчик по SHA-256; дочерний CSP запрещает прямые соединения. Ограничения браузерного механизма описаны в [Tauri CSP](https://v2.tauri.app/security/csp/) и [MDN srcdoc](https://developer.mozilla.org/en-US/docs/Web/API/HTMLIFrameElement/srcdoc). Эти свойства проверяются отдельным сценарием с производственной политикой.

Выполнение ограничено 8 секундами по умолчанию; плагин останавливается по тайм-ауту/отключению. Размер сообщения/результата — до 1 MiB, данных одного виджета через SDK — 256 KiB, JSON — до 32 уровней, до 100 000 значений. Есть защита от потока запросов. Это ограничения API и времени; отдельной гарантии верхней границы памяти Worker браузер не предоставляет. Устанавливайте расширения из известных вам исходников. Реестр ограничен 24 MiB и 30 пакетами, JS-код одного пакета — 1 MiB.

## Расширенный отдельный процесс

`runtime:"process"` использует `manifest.process:{executable,args}` и разрешение `process`, без `code`. Движок запускает явно заданный локальный `.exe`, не подставляет команду в оболочку. Пакет может явно указать интерпретатор — пример `native-stamp` использует Windows PowerShell; его исходник также поставляется отдельно.

Это широкий доступ с правами пользователя Windows. Процесс может обращаться к ОС вне разрешений Worker; он не считается изолированным от файлов или сети. Пользователь видит путь/параметры и отдельно подтверждает доверие перед каждым запуском. MCP не может включить этот режим или сам начать процесс.

Протокол — UTF-8 JSON-lines через stdin/stdout: приложение отправляет `{kind:"invoke",command,args}`, процесс вызывает SDK через `{kind:"call",id,method,args}`, получает `{kind:"reply",id,result}`/`error` и завершает команду `{kind:"result",result}`. `plugins/examples/native-stamp.ps1` показывает обмен с кириллицей. stderr не используется для протокола.

Переменные окружения приложения/его токены процессу не передаются. Рабочая папка отдельная. В Windows процесс сначала создаётся приостановленным, включается в Job Object и затем продолжает исполнение: 256 MiB памяти, 10 CPU-секунд, один процесс в задании, завершение при закрытии. Один ручной запуск обслуживает одну команду; одновременно допускаются два запущенных модуля. Режим в этой бете поддерживает Windows.

## Агент

MCP `plugins` перечисляет пакеты, команды и панели, устанавливает файл выключенным, вызывает команду, выключает/удаляет расширение. Права команды ограничиваются одновременно разрешениями плагина, ролью общей доски и сеансом агента. Для файлов действует пересечение двух выбранных папок. Разрешения и расширенный запуск подтверждаются человеком в диалоге. Подробный контракт — `docs/agent-access.md`.
