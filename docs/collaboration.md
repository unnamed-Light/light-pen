# Совместное редактирование — бета 0.4

В бету 0.4 входит клиент и отдельно запускаемый сервер совместной работы. Публичный адрес ещё не выбран и сервис в интернете не развёрнут. Длительная эксплуатационная приёмка публичного сервиса остаётся отдельным этапом.

## Модель

Существующий локальный документ остаётся локальным. Команда «Создать общую доску» отправляет отдельную копию на выбранный сервис с новым идентификатором. Сетевой документ сохраняет локальную копию и отдельный CRDT-кэш. Аккаунт не нужен для обычного редактирования файлов.

Гостю-владельцу выдаётся отдельный секрет полного управления. Приглашения редактора и наблюдателя имеют срок до 30 дней и отзываются независимо. Аккаунт использует логин/пароль; его доски и выданные членства хранятся на сервере. Гостевую доску можно закрепить за своим аккаунтом; прежний гостевой секрет владельца после этого отзывается.

Приглашение имеет вид HTTPS-адреса /join/ROOM#SECRET. Секрет находится во фрагменте, не в пути/параметрах HTTP. Для WebSocket сервер выдаёт одноразовый билет на 30 секунд. Пароли проходят scrypt; сервер хранит хэши токенов и приглашений. Клиент не записывает токены в документ или CRDT-кэш. В Windows сессии аккаунтов и доступ к комнатам сохраняются отдельно в credentials.dpapi, зашифрованном DPAPI текущего пользователя. Пароль не сохраняется. Очередь повторяет неудавшуюся запись и не заменяет нечитаемое хранилище пустым. Выход удаляет сохранённую сессию аккаунта и связанные комнаты, сохраняя независимые гостевые приглашения. «Забыть» удаляет выбранную локальную запись после подтверждения. DPAPI не заменяет приглашение или повторный вход при переносе на другой ПК/профиль Windows.

## Слияние и отмена

Yjs хранит поля каждого объекта отдельно. Текст использует Y.Text. Позиция/оформление разных объектов сливаются; изменение удалённого объекта не воскрешает его. Локальная отмена использует отслеживаемый origin и не восстанавливает старый снимок поверх чужой работы. Во время активного жеста/редактирования удалённые пакеты ожидают завершения; ввод пера остаётся локальным и отправляется завершённой операцией. Таблицы используют отдельные Y.Text ячеек и ID строк/полей; задачи — независимые поля и пункты. Подробности и оставшиеся направления: data.md. Настройки пера одного штриха и некоторые другие небольшие вложенные свойства остаются атомарными.

Локальное сохранение и подтверждение сервером — разные статусы. Сервер сначала проверяет кандидатное состояние, затем синхронно фиксирует SQLite WAL/FULL и отправляет подтверждение. Ошибочный пакет не заменяет предыдущую запись. Наблюдатель не может отправить изменения даже через прямой WebSocket. Отзыв приглашения закрывает подключённый сеанс; проверка прав повторяется при каждом пакете.

Сетевой черновик браузера — журнал бинарных пакетов IndexedDB. Запись небольшой правки не кодирует всю доску. После 300 пакетов или 4 МБ журнал объединяется в отдельном Web Worker. Переписываются только прочитанные пакеты; более новые остаются. Поколение полной копии защищает от перезаписи, если другое окно успело сохранить её во время объединения. Ошибка оставляет исходные пакеты, а не пустой документ. Старый кэш версии 1 читается. Токенов в нём нет.

Снимки модели кэшируют неизменённые объекты и точный UTF-8-размер; модель при редактировании использует новые объекты вместо изменения прежних на месте. На сервере один worker может хранить один декодированный документ с состоянием до 8 МБ. Повторное использование разрешено только при полном совпадении байтов с подтверждённой SQLite-копией. Отклонение, неподтверждённая запись и смена комнаты не могут отравить последующее состояние. Предел памяти/времени worker сохраняется.

## Запуск для разработки

Node.js 24 с node:sqlite, npm ci, npm run server. По умолчанию только 127.0.0.1:8787. Данные — server-data/collaboration.sqlite (исключены из Git). Переменные: HOST, PORT, LIGHT_PEN_DATA, LIGHT_PEN_ORIGINS, LIGHT_PEN_REGISTRATION=closed. В клиенте HTTP допустим только на loopback; публичный адрес обязан быть HTTPS.

Для проверки: npm run test:collaboration; npx playwright test tests/collaboration.spec.ts. Тесты создают изолированные комнаты/учётные записи и не используют пользовательские доски.

## Публичное размещение

Подготовлены server/Dockerfile, compose.yaml и Caddyfile. Перед запуском выбираются домен и размещение, задаётся LIGHT_PEN_DOMAIN; DNS должен вести на сервер. Порты приложения не публикуются наружу: доступ идёт через TLS-шлюз. Для развёртывания из корня: docker compose -f server/compose.yaml up -d --build. Изменение .env и сам запуск выполняются только после выбора размещения владельцем.

Перед допуском в интернет остаются обязательные ворота: ограничения диска/памяти и очередей, изоляция тяжёлой валидации, проверка прокси/rate-limit, резервное копирование с реальным восстановлением, долговременная нагрузка, обновление/откат, мониторинг и проверка TLS на выбранном хосте. Содержимое SQLite/секреты не должны попадать в access logs, дампы диагностики и Git.

Резервировать следует SQLite согласованным snapshot/backup API или при остановленном приложении; простая копия одного основного файла при активном WAL не считается резервной копией. Том данных должен сохраняться при обновлении контейнера.

Реализован CLI согласованной копии: node --import tsx server/backup-cli.ts SOURCE.sqlite NEW-BACKUP.sqlite. Существующий файл назначения не заменяется; после backup выполняется integrity_check. В тестах копия восстановила комнаты, аккаунты, сессии и приглашения при работающем исходном WAL. Проверка недоверенных обновлений перенесена в worker threads; очередь ограничена и сериализуется по комнате. Для публичного VPS остаются проверки контейнеров, реального TLS, длительной нагрузки и эксплуатационных процедур. LIGHT_PEN_TRUST_PROXY=true допустим только за доверенным шлюзом, когда порт приложения не доступен напрямую извне; иначе используется адрес TCP-соединения.

Первичные источники: https://docs.yjs.dev/api/document-updates , https://docs.yjs.dev/api/undo-manager , https://nodejs.org/api/sqlite.html , https://nodejs.org/api/crypto.html .
