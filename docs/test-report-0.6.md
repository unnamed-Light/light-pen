# Проверки Light Pen 0.6.0-beta.1

Платформа: Windows x64, Intel Core i5-13420H. Сценарии интерфейса — Playwright/Chromium, окно 1440 × 960 (отдельно 800 × 560); настольная приёмка — настоящий Tauri/WebView2. Проверки выполнены 4–5 ноября 2026 года.

Состояние: **бета готова к пользовательскому тестированию** в согласованном объёме 0.6. Скомпилированы production exe и NSIS; окончательный exe проверен через MCP и в настоящем окне Windows. Пройдены 209 проверок ядра, 47 Rust, весь набор из 106 различных UI-сценариев и 16 групп нативного MCP. Известных неустранённых критических/крупных дефектов в проверенном объёме не осталось. Предыдущий [отчёт 0.5](test-report-0.5.md) сохранён отдельно.

## Заключительные измерения

Нагрузочные сценарии выполняются последовательно, без параллельной компиляции/другого тестового набора. Фоновые пользовательские приложения не закрываются. Показатели — время CPU/подготовки, а не измерение задержки аппаратного пера или частоты обновления дисплея.

- 10 000 объектов: первый общий план 77,8 мс (отрисовка 17,3 мс, построение растрового кэша 57,3 мс); последующая камера P95 4,3 мс. Обычный вид отсекает до 110 видимых объектов, P95 3,2 мс. Первый показ укладывается в отдельный бюджет 100 мс; это не прогретый интерактивный кадр.
- Смешанный общий план 10 000 объектов с миникартой: первый показ 47,3 мс; последующая навигация P95 6,3 мс.
- Штрих 10 000 отсчётов: пакет обработчика P95 0,40 мс; активный overlay P95 1,60 мс; финальная отрисовка 2,90 мс; перерисовок основной сцены во время штриха — 0.
- Общая доска 10 000 объектов: локальная правка P95 7,2 мс, максимум 12,3 мс. Подтверждение сервера P95 553,9 мс включает сетевой/проверочный цикл; это не время рисования.
- Отдельный CPU-benchmark MCP-модели: 24 правки одного объекта на доске из 10 000, P95 17,0 мс; первый холодный вызов/максимум 80,3 мс. Измерение включает проверку/транзакцию, не является временем renderer или сетевой задержкой. `reports/agent-api-performance-0.6.json`.
- PNG 64 Мп (16 000 × 4 000): 1 196 453 байта, 1 587,7 мс, без уменьшения. Расчёт рабочей памяти — 801 569 120 байт; подробности — `reports/export-workspace/64mp-result.json`.

Плавность проверена отдельно: медленная диагональ, быстрые дуги, волна нажима, маркер, постоянный и широкий нажим, неоднородный ввод; 181–1401 точка на профиль. Разрывов — 0 во всех шести профилях. Изменение силуэта активного/завершённого штриха — 0–1,685%; overlay P95 — 0,6–1,5 мс. Толщина в пикселях при 50/100/200/400% — 4/6/12/24. Логи содержат полный набор исходных измерений, включая предыдущий прогон, а не только выбранные быстрые результаты.

## Регрессии и ограничения

Проверены независимость страниц при обычном редактировании/ползунках/отмене, сохранение старых объектов при перестановке первой legacy-страницы, единое восстановление всего пространства, одновременные CRDT-изменения страниц и поздние объекты удалённой страницы. Смена страницы/отзыв прав во время подготовки изображения, формулы, фрагмента или команды плагина отвергает запись.

Исправлены: потеря неактивных страниц при обычном commit/истории/пакете агента; отсутствие страниц в SQLite-контейнере/чтении версии; межстраничная маршрутизация стрелок; переход ссылки, блокировавшийся собственным состоянием ожидания; шаблоны с чужим pageId; статический текст виджета, не попадавший в отрисовку; необработанный optional undefined в чтении плагина; неполная копия внутренних ID задачи/таблицы; ненужный квадратичный поиск при большом переносе.

Первый полный UI-прогон дал 99 успешных сценариев и 3 находки: редактирование таблицы старого формата проверялось с неверной версией схемы; проверка шаблона ожидала сохранения исходных ID вместо независимой копии; сценарий ошибочной формулы пытался нажать уже отключённый экспорт. Исправлены реализация валидации и соответствующие проверки поведения. После этого основной набор прошёл 96/96. На ручной нативной проверке найден отдельный быстрый путь обычных прямоугольников, обходивший текст виджетов. Новая проверка пикселей сначала воспроизвела 0 текстовых пикселей, затем прошла после исправления; повторены все 5 сценариев плагинов. Исходные логи ошибок сохранены локально.

Документ/экспорт — до 64 MiB JSON / 256 MiB итогового файла; PNG — до 16 384 px и 64 Мп. Оценка рабочей памяти не резервирует RAM. Экспорт не уменьшает разрешение при превышении пределов, а возвращает явную ошибку. JS/TS-плагины работают через ограниченный SDK; расширенный процесс Windows имеет широкий доступ после ручного доверия, с указанными ресурсными пределами. Подробности — `plugins.md` и `release-0.6.md`.

Реальное давление/наклон/кнопки и фильтрация ладони аппаратного стилуса не проверены на физическом устройстве. Установщик NSIS собран; установка в основной пользовательский профиль и другие ОС не проверялись. Публичный сервер/домен не развёрнуты: это отдельный согласуемый этап. Полная функциональность Miro этим выпуском не заявляется.
